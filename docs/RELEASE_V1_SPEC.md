# 첫 공개 버전 출시 명세

상태: 개발 목표 확정. 현재 구현이나 출시 준비 완료를 뜻하지 않는다.

이 문서는 첫 공개 버전의 범위와 출시 판정을 정한다. CODEX_SPEC.md의 장기 기획보다 이 문서의 첫 출시 범위를 우선한다.

## 1. 제품과 대상

- 형식: 무료 iOS 퍼즐 앱. React 웹 코어를 Capacitor로 감싸고 광고·결제는 네이티브 어댑터로 연결한다.
- 사업 모델: 기본 무료 IAP + IAA 하이브리드 캐주얼 게임. 기본 플레이와 초기 콘텐츠를 무료로 제공하고 광고 제거 인앱결제·보상형 광고·전면 광고를 첫 출시에서 지원한다.
- 화면과 설명: 기본 영어. 단어 퍼즐은 영어 대문자를 사용한다.
- 대상: 기초 영어 단어에 익숙하고 짧게 퍼즐을 즐기는 사용자.
- 첫 공개 플랫폼: iOS / Apple App Store, iPhone 우선. Android / Google Play 대응은 후속 업데이트다.
- 개발·확인: 기존 로컬 웹 미리보기를 유지한다. 웹에서는 광고·결제를 테스트 어댑터로 표시하고 실제 과금은 하지 않는다.
- 배포: 웹 자산을 앱에 포함한다. 자체 서버·회원 계정·운영 DB 없이 기기에 저장한다.
- 네트워크: 광고에는 Google AdMob, 인앱결제·구매 복원에는 Apple 서비스와 인터넷 연결이 필요하다. 서버가 없다는 조건은 자체 서버를 운영하지 않는다는 뜻이며 외부 광고·스토어 서비스까지 제거하는 뜻이 아니다.
- 개발 환경: Windows에서 Codex·Gemini로 웹 코어와 로컬 미리보기 개발을 계속한다. 사용자가 보유한 Mac mini로 프로젝트를 옮겨 Xcode에서 iOS 빌드·서명·아카이브·TestFlight 업로드를 진행한다. 광고·결제의 실제 동작은 Mac 이동 후 iPhone에서 검증하며 웹 검증 완료를 네이티브 검증 완료로 간주하지 않는다.
- 이름·문구·화면은 자체 제작하며 참고 게임의 브랜딩과 자산을 복제하지 않는다.

## 2. 콘텐츠와 플레이 시간

첫 버전은 정식 퍼즐 20팩을 제공한다. 각 팩은 아래 4종을 하나씩 포함하며, 총 80개다. 연습 문제는 이 수량에 포함하지 않는다.

| 게임 | 수량 | 규칙 | 문제당 예상 시간 |
| --- | ---: | --- | --- |
| Password | 20 | 영어 5글자 정답, 6회 추측, 색상 피드백 | 2~4분 |
| Hashtag | 20 | 5×5 교차 단어 격자, 두 타일 교환, 최대 15회 | 3~5분 |
| Anygram | 20 | 주어진 6글자로 정답 단어 5~8개 찾기 | 3~5분 |
| Sudoku | 20 | 4×4, 2×2 구역, 숫자 1~4 | 1~2분 |

- 한 팩은 약 9~16분, 전체는 약 180~320분의 새 문제 풀이를 예상한다.
- 약 3시간은 콘텐츠 분량의 목표이며 모든 사용자의 실제 시간을 보장하는 수치가 아니다.
- 첫 진입부터 20팩 전체를 플레이할 수 있다. 날짜 대기, 에너지, 결제, 광고로 진행을 막지 않는다.
- 권장 진행은 입문 4팩 → 일반 12팩 → 도전 4팩이다. 난이도는 실제 풀이 검증 후 확정한다.
- 같은 정답·배치를 재사용한 문제나 재도전 시간을 새 콘텐츠 분량으로 계산하지 않는다.
- 현재 7일치 샘플은 후보 자료다. 정답·중복·난이도 검증을 통과한 문제만 정식 80개에 포함한다.

## 3. 기본 게임 사이클

1. 홈에서 이어하기 또는 다음 추천 팩을 선택한다.
2. 팩의 게임 4개 중 원하는 게임을 연다.
3. 짧은 규칙 안내를 보고 플레이한다. 최초 1회만 안내를 자동 표시한다.
4. 완료하면 시간·실수·힌트 수·획득 XP를 확인한다.
5. 같은 팩의 다음 미완료 게임 또는 다른 팩으로 이동한다.
6. 4종을 마치면 팩 완료를 표시한다. 20팩 완료 후에는 재도전과 신규 팩 안내를 제공한다.

한 화면에 게임 4개를 길게 나열하지 않고 선택한 게임 하나만 표시한다. 중간에 홈으로 나가도 진행도는 유지한다.

## 4. 게임 공통 규칙

- 터치 조작을 기본으로 한다. Password는 실제 키보드 입력도 지원한다.
- 각 게임에 규칙 다시 보기, 홈으로, 진행 상태, 힌트, 완료·실패 안내를 제공한다.
- 힌트는 시도당 최대 3회 무료다. 사용 전에 도움의 내용을 안내하고 남은 횟수를 표시한다.
- 힌트를 사용하거나 힌트로 마지막 칸을 완성해도 정상 클리어로 인정한다.
- 실패하면 재도전할 수 있다. 힌트가 소진되어도 플레이를 막지 않는다.
- 재도전 시 해당 시도의 보드는 초기화하지만 기존 클리어·획득 보상은 유지한다.
- 최초 클리어 보상은 퍼즐 ID당 한 번만 지급한다. 재플레이는 연습으로 구분한다.
- 무실수·무힌트 기록 판정에는 최초 클리어까지의 실패·힌트 사용 이력도 반영한다.
- 시간은 첫 조작부터 측정하고 숨겨진 탭과 접속하지 않은 시간은 제외한다.
- 정답·오답은 색상과 함께 문자나 아이콘으로도 구분한다.

### 게임별 필수 품질

- Password: 힌트가 실제 정보를 제공해야 한다. 허용 단어는 작은 문제별 예시 목록 대신 공통 영어 단어 사전으로 검증한다. 중복 글자를 정확히 판정한다.
- Hashtag: 가로·세로 6단어가 실제 단어여야 한다. 교환 전후 글자 수를 보존하고 제한 횟수 내 해법이 존재해야 한다. 정답 타일과 선택 타일을 명확히 구분한다.
- Anygram: 각 글자는 제공된 개수만큼 사용한다. 흔한 단어만 정답으로 쓰고 고유명사·약어·불확실한 단어는 제외한다. 남은 단어 길이를 표시한다.
- Sudoku: 유일해답을 기계적으로 검증한다. 주어진 숫자는 잠그고 2×2 경계를 표시한다. 오답 3회 시 실패하며 힌트가 실수로 집계되면 안 된다.

## 5. 진행과 보상

- 영구 기록: 완료한 퍼즐 ID, 팩 완료 수, 총 XP, 배지, 문제별 진행도.
- XP는 기존 기본 50·무실수 추가 25·120초 이내 추가 15 기준을 사용한다. 실패 이력과 실제 플레이 기록을 반영한다.
- 기존 8종 배지 중 스트릭 2종과 아카이브 전용 1종은 첫 버전에서 숨긴다. 나머지는 설명과 판정 조건을 일치시킨다.
- 그랜드슬램은 실제 달력 날짜와 무관하게 한 팩의 4종 완료로 정의하고 표시 이름도 변경한다.
- 미션은 플레이 세션의 팩별 목표 3개로 단순화한다: 게임 1개·3개·4개 완료. 보상은 각각 30·50·80 XP다.
- 목표는 순서대로 누적 달성되며 자동 수령한다. 별도 상자 보상과 수령 모달은 첫 버전에서 제외한다.
- XP와 배지는 날짜를 바꿔도 유지되는 전체 진행도에 저장한다. 각 보드는 퍼즐별로 분리한다.
- 코인·힌트 유료 구매·레벨 잠금은 첫 버전에서 숨긴다. 광고 제거 상점은 포함하며 소비처 없는 재화를 추가하지 않는다.

## 6. 필요한 화면

| 화면 | 반드시 있어야 할 내용 |
| --- | --- |
| 홈 | 이어하기, 추천 팩, 전체 완료 수·XP, 전체 팩 보기 |
| 팩 목록·상세 | 20팩, 난이도, 4종별 미시작·진행·완료 표시 |
| 게임 | 선택한 게임 하나, 규칙 안내, 힌트, 기록, 홈 복귀 |
| 결과 | 완료·실패, 실제 기록, 최초 보상 여부, 다음 게임·재도전 |
| 상점 | 광고 제거 상품, 스토어 현지 가격, 구매·처리 상태, 구매 복원 |
| 랭킹 | 이 기기의 개인 최고 기록, 게임별 기록, 동점 기준 안내 |
| 설정·기록 | 배지, 광고·개인정보 설정, 저장 안내, 진행 초기화와 확인 단계, 앱 버전 |

로딩·불러오기 실패·빈 콘텐츠 목록에 대한 안내와 재시도 버튼도 제공한다. 개발용 문구·가짜 수치·샘플 날짜는 제품 화면에서 제거한다.

## 7. 저장과 콘텐츠 업데이트

- 저장 형식에 버전을 둔다. 앱에서는 네이티브 영속 저장소를, 웹 미리보기에서는 localStorage를 서비스 어댑터로 사용한다. 정상 저장이 불가능하면 저장되지 않는다는 안내를 표시한다.
- 새로고침·팩 전환·브라우저 재실행 후 보드와 기록을 복원한다.
- 손상된 데이터는 복구 가능한 정상 기록을 보존하고 해당 문제만 다시 시작할 수 있게 한다.
- 사용자가 명시적으로 초기화하기 전에는 콘텐츠 업데이트로 완료 기록과 XP를 지우지 않는다.
- 설정에서 앱 데이터 삭제·삭제 후 재설치 시 플레이 기록이 사라지고 기기 간 동기화가 없음을 안내한다. 광고 제거 구매 권한은 플레이 기록과 분리하고 스토어에서 복원한다.
- 콘텐츠 목록 JSON을 도입한다. 코드의 날짜 배열을 수정하지 않고 목록과 퍼즐 JSON 추가로 팩을 늘린다.
- 목록 항목에는 고정 팩 ID, 순서, 표시 이름, 난이도, JSON 경로, 콘텐츠 버전을 둔다.
- 퍼즐 ID는 팩 ID와 게임 ID로 고정한다. 이미 배포한 문제의 정답을 바꿀 때는 새 퍼즐 ID를 발급한다.
- 실제 날짜의 오늘 추천은 기존 팩을 추천하는 기능으로만 사용한다. 추천 변경이 진행도나 보상을 초기화하지 않는다.
- 새 게임 종류 추가에는 코드 업데이트가 필요하다. 기존 4종의 문제 추가는 JSON과 목록을 추가한 앱 업데이트로 배포한다. 콘텐츠를 넣기 위해 엔진을 수정할 필요는 없다.

## 7A. AdMob 광고

- 첫 버전은 보상형 광고와 전면 광고를 포함한다. 배너·앱 오프닝 광고는 제외한다.
- 기본 힌트 3회는 무료다. 소진 후 사용자가 명시적으로 선택한 보상형 광고 1회당 추가 힌트 1회를 준다. 광고 성공 콜백을 받은 경우에만 지급한다.
- 추가 힌트를 받아도 힌트 사용 이력에 반영하며, 중복 콜백으로 보상이 중복되지 않게 한다.
- 광고 취소·실패·재고 없음·오프라인이면 힌트 잔액을 바꾸지 않는다. 재시도나 현재 상태로 계속 플레이할 수 있고 진행도를 잃지 않는다.
- 전면 광고는 최초 2개 신규 퍼즐 완료까지 표시하지 않는다. 이후 신규 퍼즐 3개 완료마다 결과 화면을 벗어날 때만 표시하되, 직전 전면 광고 노출 후 최소 180초 간격을 둔다.
- 전면 광고 카운트와 마지막 노출 시각은 저장한다. 앱 재실행이나 퍼즐 재플레이로 노출 빈도가 높아지면 안 된다.
- 플레이 도중·앱 시작 직후·구매 도중에는 전면 광고를 표시하지 않는다. 광고를 사용할 수 없으면 즉시 다음 화면으로 이동한다.
- 광고 제거 구매자는 전면 광고를 보지 않는다. 보상형 광고는 별도 혜택임을 구매 전에 알리고, 추가 힌트를 원할 때만 선택하도록 한다.
- 개발 중에는 Google 테스트 광고만 사용한다. 네이티브 SDK 생명주기·음소거·일시정지·화면 복귀를 확인한다.
- 배포 대상 지역에 맞춰 Google UMP 등으로 동의 흐름을 처리하고, 동의 상태와 SDK의 광고 요청 가능 여부를 따른다. 개인정보 선택을 다시 열 수 있게 한다.
- 첫 버전은 앱 간 추적을 사용하지 않는 광고 구성을 기본으로 한다. 실제 SDK 설정에 따라 ATT가 필요한 추적을 도입할 경우 Apple의 권한 흐름을 구현한다. ATT와 광고 동의는 별도로 처리하며 권한 거절로 기본 플레이를 막지 않는다.

## 7B. 인앱결제와 상점

- 상품은 비소모성 광고 제거 1개로 시작한다. 구독·유료 코인·소모성 힌트 판매는 제외한다.
- Apple StoreKit 2 기반 네이티브 어댑터를 사용한다. 상품 ID는 App Store Connect에서 관리하고, 가격·통화는 스토어 조회 결과를 사용한다.
- 상점은 상품 설명, 제거되는 광고 범위, 현지 가격, 구매 버튼, 구매 복원 버튼을 제공한다.
- 결제 창 호출만으로 권한을 주지 않는다. StoreKit의 검증된 구매 트랜잭션을 확인한 뒤 권한을 반영하고 트랜잭션을 완료 처리한다.
- 보류·취소·실패 상태를 구분한다. 보류 구매는 완료될 때까지 권한을 주지 않고, 앱이 종료되어도 다음 실행 시 다시 확인한다.
- 실행·복귀 시 현재 구매 권한과 트랜잭션 업데이트를 확인한다. 명시적인 구매 복원은 StoreKit 동기화 후 권한을 다시 확인한다. 환불·철회가 확인되면 로컬 권한도 갱신한다.
- 오프라인에서는 직전에 검증한 권한을 캐시로 사용한다. 조회 실패를 미구매로 처리해 기존 구매자의 광고 제거를 즉시 해제하지 않는다.
- 진행 초기화는 구매 권한을 지우지 않는다. 같은 스토어 계정으로 재설치한 경우 광고 제거를 복원할 수 있어야 한다.
- 자체 서버가 없으므로 서버에서 하는 실시간 구매 검증·환불 알림 처리는 제공하지 않는다. 온라인 재조회로 상태를 맞추며 변조 방지는 클라이언트 수준이다. 서버 권위 검증이나 부정 결제 완전 방지를 보장하지 않는다.

## 7C. 서버 없는 랭킹

- 첫 버전 랭킹은 이 기기 안의 개인 기록 순위다. 전 세계·친구 순위처럼 표시하거나 가상의 다른 사용자를 넣지 않는다.
- 표시 항목은 게임 종류, 팩, 완료 시간, 실수, 힌트 사용 수다. 게임 종류별로 개인 최고 기록과 상위 10개 풀이 기록을 제공한다.
- 무힌트 → 실수 적음 → 시간 짧음 순으로 정렬하고, 완전 동점은 먼저 기록한 순서로 표시한다. 기본 제공 숫자가 다른 Sudoku 등 조건이 달라질 때는 같은 규격끼리 구분한다.
- 같은 퍼즐 재도전은 최고 기록 갱신은 허용하되 XP를 다시 주지 않는다. 최초 클리어 기록과 연습 최고 기록을 구분한다.
- 닉네임·개인정보 수집·외부 업로드는 하지 않는다. 앱 데이터 삭제 시 기록이 사라진다는 안내를 제공한다.
- 글로벌 랭킹이 필요해지면 Apple Game Center 같은 외부 서비스 또는 별도 서버가 필요하다. 로컬 랭킹 외에 추가로 선택하는 범위이며 아래 기준으로 첫 출시 포함 여부를 판단한다.
- 온라인 리더보드가 출시 재미와 재방문에 필요하다고 판단되면 iOS에서는 Game Center를 우선 채택한다. 이미 필요한 Apple Developer 가입 비용 외에 Firebase DB·서버 운영을 추가하지 않는 구성을 우선한다. 접속·인증을 거절하거나 오프라인이어도 기본 게임은 이용할 수 있어야 한다.
- Game Center 로그인은 선택 사항이며 자체 계정을 만들지 않는다. 서로 조건이 다른 퍼즐의 시간을 단순 합산한 글로벌 순위는 제공하지 않고, 같은 퍼즐·규칙의 기록 또는 검증된 공통 점수 기준이 있을 때만 온라인 리더보드를 연다.
- Firebase는 플랫폼 간 통합 순위·운영 데이터 등 Game Center로 해결할 수 없는 요구가 생길 때 검토한다. 도입 전 무료 제공량·읽기/쓰기 예상량·초과 비용·부정 점수 방지 방식을 확인하고 가장 저렴한 구성을 사용자에게 제안한다. 유료 서비스 가입이나 과금 설정은 별도 승인을 받는다.

## 8. 출시 판정 기준

아래 항목을 모두 충족하기 전에는 출시 완료로 표시하지 않는다.

- 정식 80개 문제의 형식·정답·중복·게임별 검증이 모두 통과한다.
- Sudoku 20개 모두 유일해답이며 Hashtag 20개 모두 제한 횟수 내 해법을 갖는다.
- 게임 4종을 모두 끝까지 플레이하고 힌트 완료·실패·재도전·복귀를 검증한다.
- 중복 클릭·새로고침·팩 전환·여러 탭에서도 기록과 보상이 중복되거나 사라지지 않는다.
- 기존 저장 데이터 업그레이드, 저장소 접근 실패, JSON 로딩 실패에 대한 처리를 확인한다.
- 360px 화면에서 가로 넘침 없이 조작 가능하며 주요 버튼은 최소 44px 터치 영역을 갖는다.
- 실제 iPhone 앱에서 첫 진입부터 저장·복원까지 확인한다. 작은 화면과 Safe Area, 앱 백그라운드·복귀를 포함한다. 로컬 웹 미리보기는 네이티브 광고·결제 검증을 대체하지 않는다.
- Xcode 릴리스 빌드와 TestFlight 배포를 통과하고 Bundle ID·서명·버전·앱 아이콘·패키지 자산을 점검한다. 인증서·서명 비밀 정보는 저장소에 넣지 않는다.
- 의존성 취약점은 운영 영향과 개발 도구 영향을 구분해 점검하고 필요한 조치를 완료한다.
- AdMob SDK를 포함한 개인정보처리방침, App Store 개인정보 공개, 연령 등급, 구매 상품 설명, 필요한 개인정보 매니페스트와 SDK 설정을 준비한다. 수집·공유 데이터는 실제 동작과 일치시킨다.
- 테스트 광고로 보상 지급 1회성, 취소·실패·재고 없음, 전면 광고 간격, 구매자의 전면 광고 제거를 실기기에서 검증한다.
- StoreKit 테스트와 Apple Sandbox·TestFlight 환경으로 구매 성공·취소·보류·복원·재설치·권한 재조회 흐름을 검증한다. 실제 결제로 테스트하지 않는다.
- 동의 미완료·오프라인·스토어 연결 실패에서도 기본 80개 퍼즐과 저장 기능은 동작한다.
- 로컬 랭킹에 실제 기록만 표시되고 기록 갱신으로 XP가 중복 지급되지 않는지 확인한다.
- 개발자가 아닌 대상 사용자 3명 이상이 4팩 이상씩 플레이한다. 중앙값 기준 팩당 9~16분인지 확인하고, 더 짧다면 중복 없는 추가 문제로 약 3시간 분량을 보강한다.
- 치명적 진행 차단·저장 손실·중복 보상 결함이 남아 있지 않다. 시간 목표 달성을 위해 대기나 반복을 강제하지 않는다.

## 9. 첫 버전 제외 범위

자체 회원 로그인, 자체 서버, 기기 간 진행도 동기화, Android 배포, 구독, 유료 소모성 재화, VIP, 저금통, 독자 구축 글로벌·친구 랭킹, 멀티플레이, 스트릭 복구, 푸시, 한국어·일본어 단어 퍼즐은 후속 업데이트로 남긴다. Game Center는 필요성을 확인한 경우 첫 버전에 포함할 수 있다.

## 10. 구현 순서와 역할

1. 콘텐츠 목록과 버전 있는 저장 형식, 전체 진행도·XP·배지로 구조를 정리한다.
2. 홈 → 팩 선택 → 게임 하나 → 결과의 흐름을 만든다.
3. 기존 4종의 힌트·실패·재도전·입력·접근성 문제를 마무리한다.
4. Capacitor iOS 앱과 네이티브 저장·AdMob·StoreKit 어댑터를 연결한다.
5. 상점·광고 제거 복원·보상형 광고·기기 내 랭킹을 완성한다.
6. 20팩을 확보하고 자동 검증을 통과한 데이터만 등록한다.
7. iPhone 실기기·시간 목표·광고·결제 검증과 TestFlight 테스트 후 App Store 심사에 제출한다.

- Gemini: 후보 퍼즐 대량 생성, 단어·힌트 초안, 화면·규칙 문구 초안.
- Codex: 데이터 자동 검증, 엔진·저장·UI 통합, 회귀 검증, 배포 준비.
- 사용자: Gemini 결과 전달, 실제 iPhone 플레이와 사용성·시간 확인, Apple Developer·App Store Connect·AdMob 계정 및 앱·광고 단위·상품 설정, 보유 Mac mini에서 최종 네이티브 빌드·테스트·TestFlight 작업, 비공개 경로의 인증서·서명 정보 관리, 공개 배포 승인.

### Mac mini로 넘길 때

- 소스·의존성 잠금 파일·콘텐츠 목록·검증 스크립트와 재현 가능한 실행 절차를 준비한다. Windows의 node_modules를 복사하지 않고 Mac에서 의존성을 다시 설치한다.
- Capacitor iOS 프로젝트, 네이티브 플러그인 버전, 필요한 Xcode·iOS 설정과 Bundle ID를 문서로 정리한다.
- AdMob 앱·광고 단위 ID, StoreKit 상품 ID, 필요 시 Game Center 설정 항목을 구분한다. 인증서·계정 자격 증명은 공개 저장소나 Gemini 프롬프트에 넣지 않는다.
- Mac 이전 직후 개발용 iPhone 빌드를 실행해 광고·구매·복원·동의 흐름을 확인한 다음 릴리스 아카이브와 TestFlight 검증으로 넘어간다.

다음 콘텐츠 업데이트는 기존 저장을 보존하는 신규 팩 5개 단위로 진행한다. 실제 사용자 소요 시간과 피드백으로 이후 추가 주기를 정한다.
