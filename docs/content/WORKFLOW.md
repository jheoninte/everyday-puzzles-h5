# 첫 출시 콘텐츠 준비

현재 플레이 가능한 7팩은 출시 후보 자료다. `current-audit.json`은 2026-11-17 자동 검사 결과이며 7팩 모두 출시 구조 조건 중 하나 이상을 충족하지 못한다. 같은 Password 정답, Hashtag 정답 격자 재사용, 정답 수가 사양(5–8개)과 다른 Anygram, 복수 해답 스도쿠가 포함된다. 영단어 사전 등재 여부·사용 빈도는 이 구조 검사의 범위 밖이다. 기존 플레이 기록을 지키기 위해 후보 정답과 ID는 이번 단계에서 변경하지 않았다.

## 역할과 실행

1. Gemini에 `docs/GEMINI_CONTENT_PROMPT.md`의 프롬프트를 전달한다. 공통 5글자 단어 500개 이상, 새 Password 20개, Anygram 20개를 하나의 JSON으로 받는다. 불필요한 코드·스도쿠·교차 격자는 요청하지 않는다.
2. `npm run content:sudoku`로 출시용 스도쿠 20개를 생성한다. 고정 시드이며 유일해답과 서로 다른 정답 보드를 확인한다. 결과는 `content/staging/sudoku.json`. 난이도는 단서 수에 따른 임시 분류다.
3. 받은 JSON 파일을 입력으로 `npm run content:stage -- "파일경로"`를 실행한다. 입력 단어 은행으로 로컬 제약 탐색기가 Hashtag 20개를 구성한다. 동일 단어는 격자당 한 번, 전체 격자에서 최대 3번 사용한다. 정답/전치 격자의 중복은 차단한다. 글자 은행이 부족하면 보강을 요청하며 임의 단어를 만들지 않는다.
4. 20팩 전부 구조 검증을 통과한 경우에만 `content/staging/release/`에 팩·manifest·풀이 증빙을 출력한다. 검증 실패 시 공개 파일은 수정하지 않는다. 이전 실행의 staging 결과가 있다면 최신 성공 결과로 간주하면 안 된다.
5. 단어·힌트를 교정하고 영어권 일반 사용자가 이해할 수 있는지 검토한다. 공통 500단어 은행은 후보 목록이며 완전한 영어 사전이 아니다. 출시 전 일반적인 추측 단어가 부당하게 거절되지 않는지 확인하고 라이선스가 확인된 단어 목록 등으로 보강한다.
6. 실제 네 엔진에서 전체 80문제 완료·힌트·실패·재도전을 검증한다. 그 뒤 공개 경로로 복사하고 manifest를 전환한다. 기존 후보 ID의 정답을 덮어쓰지 않는다. 후보 팩을 이미 플레이한 사람의 접근/이전 정책도 전환 시 정한다.
7. 사용자 3명 이상이 각각 4팩 이상 플레이하여 팩당 중앙값 9–16분을 확인한다. 80문제라는 수량만으로 3시간을 검증했다고 표시하지 않는다.

## 자동 검증

- `npm run content:audit`: 현재 공개 manifest 감사. 오류가 남아 있으므로 현재는 종료 코드 1이 정상적인 발견 결과다.
- `npm run test:content`: 스도쿠 20개 유일해답, 틀린/복수 해답 거부, 글자 개수 제한, 교차 불일치, 교환 풀이 증빙 및 생성기 회귀 검사.
- Password: 5글자·6회, 중복 정답, 정답의 공통 사전 포함, 정답을 포함하지 않는 힌트.
- Anygram: 서로 다른 6글자 멀티셋, 목표 5–8개·중복 없음·글자 개수 준수. 출시 입력은 3–6글자 목표와 6글자 단어 하나 이상을 요구한다.
- Hashtag: 5×5 고정 구조·6개 서로 다른 교차 단어, 글자 멀티셋 보존, 실제로 재현 가능한 15회 이하 교환 해법. 생성 스크램블은 최대 10회로 풀린다. 해법의 최적성은 주장하지 않는다.
- Sudoku: 4×4/2×2 규칙·단서와 정답 일치·빈칸 존재·유일해답. 20개 정답 보드 중복 없음.

영문 의미·단어의 실재성, 재미, 난이도와 플레이 시간은 자동 구조 검증과 별도의 출시 조건이다. 현재 공개 게임은 여전히 7팩/28문제이며, 새 80문제가 통합되었다고 표시하지 않는다.
